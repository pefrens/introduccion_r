Usando read_csv()

Configuración

Primero, cargar el paquete tidyverse:

library(tidyverse)

El paquete readr (parte de tidyverse) proporciona funciones para leer datos.

Leer un Archivo CSV

# Sintaxis básica
planes <- read_csv("data/catalogo_planes.csv")

# Ejemplo con datos de estudiantes
ciudades_mundo <- read_csv("data/ciudades_mundo.csv")

read_csv() imprime información útil:

  • Número de filas y columnas
  • Delimitador usado
  • Especificación de columnas (tipos de datos)

Mensaje de read_csv()

Note

Este mensaje es importante y útil. Te dice cómo readr interpretó tu archivo.

Rutas de Archivos

Dos formas de especificar la ubicación del archivo:

# 1. Ruta relativa (dentro de tu proyecto)
planes <- read_csv("data/catalogo_planes.csv")

# 2. Ruta directa
planes <- read_csv("D:/User/curso/catalogo_planes.csv")

Tip

Las rutas relativas son más reproducibles. Usa RStudio Projects para organizarte.

Problemas Comunes: Valores Faltantes

¿Ves algún problema en los datos de ciudades?

  • Fila 3: Population tiene "N/A" (texto) en lugar de NA (valor faltante)
  • Fila 5: Population tiene "un millón" (texto) en lugar de 1000000 (número)
  • Fila 6: Population tiene cadena vacía ""

Solución: Argumento na

Especifica qué cadenas deben interpretarse como valores faltantes:

ciudades <- read_csv(
  "data/ciudades.csv",
  na = c("N/A", "")  # Reconocer "N/A" y "" como NA
)

Ahora Population tiene verdaderos NA:

3  3 Andorra la Vella Andorra     <NA>     Parish
6  6 Luanda           Angola      <NA>     Province

Problemas Comunes: Nombres de Columnas

Los nombres de columnas tienen espacios:

  • City ID
  • City Name
  • Region Type

En R, estos son nombres no sintácticos y necesitan backticks:

ciudades$`City ID`   # Necesita backticks
ciudades$City ID     # ❌ Error!

Solución 1: rename()

Renombrar manualmente con rename():

ciudades |>
  rename(
    city_id = `City ID`,
    city_name = `City Name`,
    region_type = `Region Type`
  )

Solución 2: janitor::clean_names()

La forma más fácil y recomendada:

library(janitor)
ciudades |>
  clean_names()
# A tibble: 8 × 5
  city_id city_name         country               population region_type
    <dbl> <chr>             <chr>                 <chr>      <chr>      
1       1 Dubai             United Arab Emirates  3500000    Emirate    
2       2 Kabul             Afghanistan           4200000    Province

Tip

clean_names() convierte todos los nombres a snake_case automáticamente.

Problemas Comunes: Tipos de Datos

La columna population es character (<chr>) pero debería ser numérica:

ciudades |>
  clean_names() |>
  glimpse()
$ population    <chr> "3500000", "4200000", NA, "500000", "un millón", NA, "22000", "1200"

¿Por qué population es character?

Porque tiene "un millón" (texto) mezclado con números.

Solución: Limpiar y Convertir

ciudades <- ciudades |>
  clean_names() |>
  mutate(
    population = parse_number(if_else(population == "un millón", "1000000", population))
  )

Qué hace este código:

  1. if_else(): Si population es "un millón", cámbialo a "1000000", si no déjalo igual
  2. parse_number(): Convierte texto a número

Variables Categóricas: Factores

region_type debería ser un factor (variable categórica):

ciudades <- ciudades |>
  clean_names() |>
  mutate(
    region_type = factor(region_type)
  )

Ahora region_type es <fct> en lugar de <chr>:

$ region_type   <fct> Emirate, Province, Parish, County, Capital

Pipeline Completo de Limpieza

ciudades <- read_csv("data/ciudades.csv", na = c("N/A", "")) |>
  clean_names() |>
  mutate(
    region_type = factor(region_type),
    population = parse_number(if_else(population == "un millón", "1000000", population))
  )
ciudades

Trabajando con Hojas de Cálculo (Excel)

Introducción a Hojas de Cálculo

  • Microsoft Excel es ampliamente usado para organizar datos
  • Los datos se almacenan en hojas (worksheets) dentro de libros (workbooks)
  • Excel permite múltiples hojas en un solo archivo
  • Importante: Leer el artículo Data Organization in Spreadsheets (Broman & Woo, 2018)

Tipos de Datos en Excel

Excel almacena datos internamente diferente a como los muestra:

  • Booleanos: TRUE, FALSE, NA
  • Números: Todos son decimales (no hay enteros)
  • Fechas: Almacenadas como número de días desde 1900-01-01
  • Texto: Cadenas de caracteres

Cuidado

Lo que ves en Excel puede no ser lo que está almacenado. Por ejemplo, “10” podría ser número o texto.

Escribir a Excel

library(writexl)

# Crear datos de ejemplo

# Escribir a Excel

Importar Datos Espaciales

Introducción a Datos Espaciales

  • Datos geográficos representan ubicaciones en la superficie terrestre
  • Dos modelos principales: vectorial y ráster
  • Vector: puntos, líneas, polígonos (ubicaciones discretas)
  • Ráster: celdas/píxeles en una cuadrícula (fenómenos continuos)

Paquete sf para Datos Vectoriales

library(sf)  # Simple Features for R

sf proporciona:

  • Clases para datos geográficos vectoriales
  • Interfaz a GDAL (lectura/escritura de formatos)
  • Interfaz a GEOS (operaciones geométricas)
  • Interfaz a PROJ (sistemas de coordenadas)
  • Compatible con tidyverse

Sistemas de Coordenadas (CRS)

Dos tipos principales:

Geográficas (lon/lat)

  • Grados de longitud/latitud
  • Ejemplo: WGS84 (GPS)
  • EPSG:4326

Proyectadas (x/y)

  • Metros o pies
  • Superficie plana
  • Ejemplo: UTM
  • Mejor para cálculos

  clean_names() |>
  st_transform(crs = "EPSG:32718")  # Proyectar a UTM

Comparación de Formatos

Formatos Tabulares

Formato Velocidad Tipos preservados Compatible otros lenguajes Tamaño archivo Notas
CSV Media ❌ No ✅ Sí Grande Texto plano, universal
Excel Media-Lenta ⚠️ Parcial ✅ Sí Medio Problemas con fechas/precisión
RDS Rápida ✅ Sí ❌ No (solo R) Pequeño Comprimido, R nativo
Parquet Muy rápida ✅ Sí ✅ Sí (Python, etc.) Muy pequeño Columnar, Big Data

Comparación de Formatos

Formatos Espaciales

Formato Velocidad Tipos preservados Compatible otros lenguajes Archivos Notas
Shapefile Media ❌ No ✅ Sí Múltiples (4+) Límite 10 chars columnas, no DateTime
GeoPackage Rápida ✅ Sí ✅ Sí 1 único Moderno, basado en SQLite
GeoJSON Media ⚠️ Parcial ✅ Sí 1 único Texto plano, grande
GeoParquet Muy rápida ✅ Sí ✅ Sí (Python, etc.) 1 único Experimental, muy eficiente

Tip

Recomendaciones:

  • Tabular: Usa Parquet para datos grandes, RDS para uso interno en R
  • Espacial: Usa GeoPackage (reemplaza Shapefile), evita Shapefile para nuevos proyectos
  • Excel: Solo para compartir con usuarios no técnicos

Resumen de la Sesión

Lo que Aprendimos Hoy

  • ✓ Leer archivos CSV con read_csv()
  • ✓ Trabajar con hojas de cálculo Excel (readxl)
  • ✓ Importar datos espaciales con sf
  • ✓ Manejar valores faltantes con el argumento na
  • ✓ Limpiar nombres de columnas con janitor::clean_names()
  • ✓ Especificar y corregir tipos de datos
  • ✓ Leer múltiples archivos/hojas a la vez
  • ✓ Guardar datos en diferentes formatos
  • ✓ Entender sistemas de coordenadas (CRS)

Buenas Prácticas

  1. Siempre revisa los datos después de importar (glimpse(), head())
  2. Especifica valores NA explícitamente
  3. Limpia nombres inmediatamente con clean_names()
  4. Documenta qué archivos importaste y por qué
  5. Guarda versiones limpias en formatos que preserven tipos
  6. Usa rutas relativas dentro de proyectos

Error Solución
